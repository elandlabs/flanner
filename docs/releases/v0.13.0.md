# v0.13.0

A release about the parts of flanner a person meets first and the parts a
team relies on: memories you can organise, a tool that tells you when it is
out of date, onboarding that fits who you are, and review rules that hold
when someone leaves a team. The full list is in the
[changelog](../../CHANGELOG.md#0130---2026-09-18).

## Teams: upgrade everyone

If your team shares plans, memories or reviews across devices, this is the
release to move to. Seven faults found by running real devices behind
simulated home routers and carrier-grade NAT are fixed here, among them:
shared memories and review events were refused by every receiving device,
a plan pushed to you never became a file, and two teammates sharing the same
words stopped a third device syncing for good. The changelog lists all
seven.

Crash reports are built into this release but not switched on: it has
nowhere to send them, so `flanner init` does not ask.

## Before you upgrade

The first 0.13.0 process to open your store moves the database to schema 5.
An older flanner still running, such as an MCP server your agent started
earlier, refuses the upgraded store until it restarts. Restart your agents
and `flanner web` after upgrading.

## Tags and related memories

A memory can now carry topic tags. Add them when saving, or change them
later without making a new version:

```
flanner mem remember "Tokens rotate daily" --category fact --tag auth
flanner mem tag <id> billing --remove auth
flanner mem list --tag auth
flanner mem show <id> --related
```

"Related" says why each memory is there: a correction link, the same source
file or plan, or shared tags. Agents get the same through `memory_tag`,
`memory_tags`, and `tags=` / `related=` on the existing tools. Tags stay on
your machine when a memory is shared.

## Knowing when to upgrade

If you allow it at `flanner init`, flanner asks pypi.org for the latest
version number once a day, and says so on your first command of the day
and in the web UI. `flanner updates off` stops it.

## Teams

- A teammate's review counts only as the person who signed it, and approving
  in a team workspace is confirmed in the console.
- Approvals do not count while the team roster is in its grace period, and a
  removed teammate stops being served within a day.
- Entitlements renew as you sync, instead of only on `whoami --refresh`.
- Agents can ask for risky actions, and only ask; you apply them.

## Everything else

The web UI can now do what the CLI does for setup and memory, opens with
what needs you, and pages every list. `flanner status` shows whether an
agent has actually reached flanner. See the changelog for the rest.
